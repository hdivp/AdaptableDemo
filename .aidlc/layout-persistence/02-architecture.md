# Architecture: Layout persistence

## Approach
Delivered as a `GridPlugin` (the seam in `packages/grid-core/src/types.ts`, run by `internal/runPlugins.ts`), using the existing `ToolbarItem` slot that `GridCore.tsx` already renders above the grid, so `GridCore.tsx` does not change.
A factory `createLayoutPlugin(options)` returns the plugin plus a small handle (`setLayouts`) backed by a per-instance store, so the consumer can replace the list after bind without touching `config` (changing `config` rebuilds `columnDefs` and would reset column state).
State is captured and applied only through AG Grid 32 APIs checked with ag-mcp: `getColumnState`/`applyColumnState`, `getFilterModel`/`setFilterModel`, `isPivotMode`/`setGridOption('pivotMode')`, `resetColumnState`.

## Design decisions
| Id | Decision | Why | Rejected |
| --- | --- | --- | --- |
| D-01 | A factory `createLayoutPlugin(options)` returning `{ plugin, setLayouts }`. The consumer creates it once per grid (module level or `useState` initialiser) and puts `plugin` in `config.plugins`. | `ToolbarItem` only gets `ctx`. A stable plugin with its own store lets the consumer push a new list (FR-25) without changing `config`, which would rebuild `gridOptions` and reset columns. | Passing the list via `config` / a new plugin per render (re-folds options, loses grid state); adding a `layouts` prop to `GridCore` (feature code in core). |
| D-02 | A tiny per-instance store (plain object with `getSnapshot`/`subscribe`) read by the toolbar through React 18 `useSyncExternalStore`. Holds `layouts`, `currentId`, and the live `api`. | Immediate list updates (FR-24) and external replacement (FR-25) both re-render the pop-up with no extra dependency. | React context (needs a provider around `GridCore`); a state library (new dependency). |
| D-03 | Layout state = `{ version: 1, columnState, filterModel, pivotMode }` from `getColumnState()`, `getFilterModel()`, `isPivotMode()`. | Exactly the FR-06 set; excludes scroll, selection and group expansion by construction (FR-07). Plain JSON (NF-02). `version` allows a later format change. | `api.getState()` / `initialState` (GridState): includes scroll, row selection, expanded groups and focused cell, which would need stripping, and v32 has no `setState` for applying after creation. |
| D-04 | Apply order: `setGridOption('pivotMode', state.pivotMode)`, then `applyColumnState({ state: columnState, applyOrder: true, defaultState: { sort: null, rowGroup: null, pivot: null, pinned: null } })`, then `setFilterModel(filtered)`. | Pivot mode first so pivot/value columns land correctly. `defaultState` clears sort/group/pivot/pin on columns the layout does not mention (columns added since it was saved). | `applyColumnState` without `defaultState` (leaves stale sort/group on new columns). |
| D-05 | Unknown columns (FR-21): column state is passed as-is (v32 `applyColumnState` counts unmatched ids silently and returns `false`); the filter model is filtered to keys where `api.getColumn(key)` exists before `setFilterModel`. | Verified in installed 32.3.9 source: `setFilterModel` calls `_warnOnce("no column found for colId")` for unknown keys; `applyColumnState` does not warn. Filtering keeps the console clean. | Filtering column state too (would drop the auto group column `ag-Grid-AutoColumn` state when grouping is not yet active). |
| D-06 | Default = `resetColumnState()` + `setFilterModel(null)` + `setGridOption('pivotMode', boundPivotMode)`. `boundPivotMode` is read in the plugin's `applyGridOptions` (`options.pivotMode ?? false`). | `resetColumnState` is documented as "back to what was defined in the Column Definitions", which is FR-14 even when an initial layout was applied. Pivot mode is a grid option, not column state, so it must be captured separately. | Snapshotting state at `onGridReady` as "default" (wrong if an initial layout or `autoSizeStrategy` ran first). |
| D-07 | Initial layout is applied in the plugin's `onGridReady`, by applying whatever layout `currentId` points to (initially `options.initialLayoutId` if present in the list, else Default/no-op). | Works for first render and for the grid being recreated (StrictMode in `apps/demo/src/main.tsx` mounts twice in dev). | Converting the layout to `initialState` in `applyGridOptions` (different format; see D-03). |
| D-08 | Ids generated by the wrapper: `crypto.randomUUID()` when available, else `layout-<Date.now() base36>-<Math.random() base36>`; regenerated until not present in the current list (FR-09). | `randomUUID` is missing on non-secure origins; the fallback plus the uniqueness loop meets FR-09 without a dependency. | A `uuid` package (new dependency). |
| D-09 | Consumer events are callbacks on the factory options: `onLayoutCreate(layout)`, `onLayoutUpdate(layout)`, `onLayoutDelete(id)`, `onLayoutApply(id \| null)`. `null` is the Default marker, exported as `DEFAULT_LAYOUT_ID = null`. Each fires once, synchronously, after the store has changed. Closing the pop-up or cancelling fires nothing. | Matches the existing callback style (`onGridReady` prop). `null` cannot collide with a consumer id string. | An event emitter / DOM events (more surface, no benefit); a magic string such as `"__default__"` (could collide). |
| D-10 | The wrapper never persists (FR-18): no `localStorage`, `sessionStorage`, `fetch` or cookies anywhere under `plugins/layouts`. Wrapper-created layouts live only in the store; `setLayouts(list)` replaces the whole list. | FR-18, FR-25, out-of-scope list. | Merging lists (explicitly out of scope). |
| D-11 | Current marker rules: apply sets it to that id; Default sets it to `null`; create and update set it to the created/updated id (the grid now matches it); delete of the current layout sets it to `null` without changing the grid; `setLayouts` that drops the current id sets it to `undefined` ("none marked") without changing the grid. | FSD leaves the dropped-current case to the architect. Marking Default would be a lie because the grid is not in Default. | Re-applying Default on replace (changes the user's grid unexpectedly). |
| D-12 | UI: the toolbar item renders a "Layout" button; the pop-up is a modal-style panel over the grid (like Adaptable's), plain React + CSS inside grid-core. Rows: "Default layout" first, then each layout by name, current one marked "(current)". Per row: Apply; for named rows also Update (with an editable name field, pre-filled) and Delete (inline "Delete X? Confirm / Cancel"). "Create new" opens an inline name field with Save / Cancel. Validation messages show inline; Escape, a Close button and clicking the backdrop close it. | No new UI dependency; everything stays inside `packages/grid-core/src`. Inline confirm/name inputs avoid `window.prompt`/`confirm`, which the tester cannot style or reliably drive. | A UI library dialog (new dependency); `window.prompt` / `window.confirm`. |
| D-13 | Name validation (FR-19): `name.trim()` must be non-empty and not equal, case-insensitively after trim, to any other listed layout's trimmed name (the one being renamed is ignored). The stored name is the trimmed name. "Default layout" is not a reserved name. | Straight from FR-19; keeping it pure makes it reusable by create and update. | Reserving "Default layout" (not in the FSD). |
| D-14 | Consumer-passed lists are trusted: not re-validated or de-duplicated. | The consumer owns the data; the FSD sets no rule for bad input. | Silently dropping duplicates (hides consumer bugs). |

## Contracts
```ts
// packages/grid-core/src/plugins/layouts/types.ts
import type { ColumnState, FilterModel } from "ag-grid-community";

/** Opaque to the consumer. Store and return it unchanged; it survives JSON. */
export interface GridLayoutState {
  version: 1;
  columnState: ColumnState[];
  filterModel: FilterModel;
  pivotMode: boolean;
}

export interface GridLayout {
  id: string;
  name: string;
  state: GridLayoutState;
}

/** Id of a layout, or null meaning "Default layout". */
export type GridLayoutId = string | null;
export const DEFAULT_LAYOUT_ID: null;

export interface LayoutPluginOptions {
  /** Saved layouts supplied at bind time. May be empty. */
  layouts: GridLayout[];
  /** Start in this layout. Absent or unknown -> Default. */
  initialLayoutId?: string;
  onLayoutCreate?: (layout: GridLayout) => void;
  onLayoutUpdate?: (layout: GridLayout) => void;
  onLayoutDelete?: (id: string) => void;
  onLayoutApply?: (id: GridLayoutId) => void;
}

export interface LayoutPluginHandle<TRow = unknown> {
  /** Put this in config.plugins. Keep the same instance for the grid's life. */
  plugin: GridPlugin<TRow>;
  /** Replace the wrapper's list entirely (FR-25). Does not change the grid. */
  setLayouts: (layouts: GridLayout[]) => void;
}

export function createLayoutPlugin<TRow = unknown>(
  options: LayoutPluginOptions,
): LayoutPluginHandle<TRow>;
```

```ts
// layoutStore.ts (internal)
interface LayoutStoreSnapshot {
  layouts: readonly GridLayout[];
  /** string = that layout, null = Default, undefined = none marked (D-11). */
  currentId: GridLayoutId | undefined;
}
interface LayoutStore {
  getSnapshot(): LayoutStoreSnapshot;          // stable object between changes
  subscribe(listener: () => void): () => void;
  replace(layouts: GridLayout[]): void;
  add(layout: GridLayout): void;
  update(layout: GridLayout): void;
  remove(id: string): void;
  setCurrent(id: GridLayoutId | undefined): void;
}

// layoutState.ts (internal)
function captureLayoutState(api: GridApi): GridLayoutState;
function applyLayoutState(api: GridApi, state: GridLayoutState): void;
function resetToDefault(api: GridApi, boundPivotMode: boolean): void;

// layoutRules.ts (internal)
type NameCheck = { ok: true; name: string } | { ok: false; message: string };
function validateLayoutName(
  raw: string, layouts: readonly GridLayout[], ignoreId?: string,
): NameCheck;
function generateLayoutId(layouts: readonly GridLayout[]): string;
```

## Library notes
| Library | Version in use | Note from the docs |
| --- | --- | --- |
| ag-grid-community | ^32.2.0 (32.3.9 installed) | `getColumnState()` / `applyColumnState({ state, applyOrder, defaultState })`. `undefined` = leave alone, `null` = clear (except width). `applyOrder: true` is needed to restore column order. Index variants (`rowGroupIndex`, `pivotIndex`) win over booleans. |
| ag-grid-community | 32 | `resetColumnState()` returns columns "to what was defined in the Column Definitions". |
| ag-grid-community | 32 | `getFilterModel()` / `setFilterModel(model \| null)`; `null` clears all. Unknown colIds trigger `_warnOnce("setFilterModel() - no column found for colId")` (checked in installed source), so filter keys first. |
| ag-grid-community | 32 | `pivotMode` is a grid option: read with `api.isPivotMode()`, set with `api.setGridOption('pivotMode', v)`. |
| ag-grid-community | 32 | `api.getState()` / `initialState` exist but include row selection, expanded groups, scroll and focus; v32 has no `api.setState`. Not used (D-03). |
| ag-grid-community | 32 | `autoSizeStrategy` (the demo uses `fitGridWidth`) is `@initial` and runs on load; it may resize columns after `onGridReady`. See Risks. |
| ag-grid-community | 32.2 docs vs 32.3.9 installed | Row selection: 32.2 docs show `selection: { mode: 'multiRow' }`; the installed 32.3.9 types expose `rowSelection?: RowSelectionOptions \| 'single' \| 'multiple'`. Use whichever the installed types accept (`rowSelection: { mode: 'multiRow' }`); typecheck decides. Demo only. |
| ag-grid-enterprise | ^32.2.0 | Row grouping, aggregation, pivot and the side bar are Enterprise; already registered by the `import "ag-grid-enterprise"` in `GridCore.tsx`. |
| react | ^18.2.0 | `useSyncExternalStore` is available in React 18; `getSnapshot` must return the same object until the store changes. |

## Risks
| Risk | What to do about it |
| --- | --- |
| The demo's `autoSizeStrategy: fitGridWidth` may resize columns after `onGridReady`, overwriting the initial layout's widths (AC-20). | Developer checks in the running demo. If widths are lost, apply the initial layout once more on the grid's `firstDataRendered` event (added via `api.addEventListener` in `onGridReady`, removed in cleanup), or drop `autoSizeStrategy` from the demo when `?initialLayout` is set. Do not touch `GridCore.tsx`. |
| React StrictMode (demo) mounts twice; `GridCore` cleanup calls the plugin cleanup and the grid may be recreated. | Plugin cleanup only detaches the api; the store (list, current id) survives. `onGridReady` re-applies the current layout each time (D-07). |
| Creating the plugin inside a component body without memoising gives a new `plugins` array every render, re-folding `gridOptions` and resetting columns. | Demo creates it at module level. JSDoc on `createLayoutPlugin` states "create once per grid". |
| Group/pivot/aggregation cannot be exercised in today's demo (no `enableRowGroup` etc.), blocking FR-06 testing. | Demo config enables them (Files table). `agGridOptions.defaultColDef` replaces the wrapper's `defaultColDef` wholesale (shallow merge in `buildGridOptions`), so either repeat the wrapper defaults there or set the flags per column via `agColDef`. |
| Row selection option name differs between 32.2 docs and the installed 32.3.9 types. | Use the installed types; typecheck is the arbiter. |
| Pop-up z-index versus AG Grid's own popups and the side bar. | Render the pop-up with `position: fixed` backdrop and a z-index above `.ag-root-wrapper`; verify visually. |
| Re-exporting AG Grid types (`ColumnState`, `FilterModel`) in the public d.ts. | Acceptable: `types.ts` already re-exports `GridApi`/`ColDef` types. The demo never names them, so it still has no AG Grid import. |

## Handoff
- Seam: a `GridPlugin` with `ToolbarItem`, `applyGridOptions` and `onGridReady`, built by `createLayoutPlugin(options)` in `packages/grid-core/src/plugins/layouts/`. Copy the plugin shape from `packages/grid-core/src/types.ts`; `GridCore.tsx` must not change.
- Build first: `types.ts`, `layoutRules.ts`, `layoutState.ts`, `layoutStore.ts`, then `createLayoutPlugin.ts`, then the UI (`LayoutToolbarItem.tsx`, `LayoutPopup.tsx`, `layouts.css`), then exports in `src/index.ts`.
- Story build order: US-01, US-02, US-03, US-04, US-05, US-06, US-07, US-08.
- The demo work (`layoutsDb.ts`, `gridConfig.ts`, `App.tsx`, `App.css`) ships with US-01 and grows per story: query switches `?layouts=off` and `?initialLayout=<id>`, the event log, the "Replace layouts from server" button, and enabling grouping/pivot/aggregation/multi-row selection.
- AG Grid 32 APIs only: `getColumnState`, `applyColumnState({ applyOrder: true, defaultState })`, `resetColumnState`, `getFilterModel`/`setFilterModel`, `isPivotMode`/`setGridOption('pivotMode')`, `getColumn`. Set ag-mcp to 32.2.0/react before any lookup; the installed package is 32.3.9.
- Filter the filter model to existing columns before `setFilterModel` (it warns on unknown ids); pass column state through unfiltered.
- Default marker is `null` (`DEFAULT_LAYOUT_ID`); current-marker rules are in D-11.
- No storage APIs under `plugins/layouts`; no new dependencies; no version bumps.
- Verify with `npm run typecheck && npm run build`; no test command exists, so the tester drives the demo with the ACs above.
