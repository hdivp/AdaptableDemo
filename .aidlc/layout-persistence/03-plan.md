## Order and reason
Foundation and the plugin seam come first (T-01 to T-03), so T-03 proves in the running demo that a `GridPlugin` toolbar item works with no `GridCore.tsx` change before any feature logic is built; capture/create then apply follow because every later story depends on them.
After that, stories run in the architect's order (US-02 to US-08); each story's acceptance task comes after the tasks it needs (US-01's waits for create because AC-19 needs it, US-02's waits for apply because AC-24 needs it).

## Handoff
- Start at T-01; T-03 is the approach check (Layout button above the grid in the demo, gone with `?layouts=off`).
- Seam: a `GridPlugin` with `ToolbarItem`, `applyGridOptions`, `onGridReady` and cleanup, built by `createLayoutPlugin` in `packages/grid-core/src/plugins/layouts/`; copy the shape from `packages/grid-core/src/types.ts`.
- Do not touch `GridCore.tsx`, `packages/grid-core/src/types.ts`, `internal/*` or any `package.json`; no new dependencies, no version bumps.
- AG Grid imports stay inside `packages/grid-core/src`; the demo only uses `config.plugins` and the public exports.
- AG Grid 32 APIs only (see architecture Handoff); set ag-mcp to `32.2.0`/`react` before any lookup. Installed package is 32.3.9.
- Filter the filter model by `api.getColumn`; pass column state through unfiltered (D-05).
- Current-marker rules are D-11; Default marker is `null`; callbacks fire once, after the store changes, never on close/cancel.
- No storage, `fetch` or cookie use under `plugins/layouts` (D-10).
- Create the plugin once at module level in the demo; plugin cleanup detaches only the api so the store survives StrictMode remounts.
- Fast verify: `npm run typecheck`; full verify: `npm run typecheck && npm run build`. No test command; acceptance tasks are checked in the running demo.
